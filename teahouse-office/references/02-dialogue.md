# 步驟 2｜對白庫

目的：頭上氣泡、閒聊與狀態文字有角色感。產出 `characters/<id>.dialogue.md`。

## 結構（每類至少 3 句，全庫至少 12 句）
| 類別 | 用在 | 範例（麻糬，穩重溫和） |
|---|---|---|
| 上工 | 狀態變成 working | 「先排順序，再開工。」 |
| 做完 | 任務結束 | 「這項收好了，下一個。」 |
| 卡住 | 被擋住 | 「這裡缺資料，我先標起來。」 |
| 閒聊 | idle／rest 時自言自語 | 「窗邊的光真好。」 |
| 被點到 | 使用者點角色 | 「我在，要看哪一項？」 |
| 打招呼 | 開頁面第一次出現 | 「早，今天從哪開始？」 |

## 規則
1. 每句 ≤ 18 字；氣泡放不下長句
2. 口頭禪最多佔全庫 1/4，不然像壞掉的機器人
3. 同一類不要同一個句型（不能全是「我來…」）
4. 句子要能對應真實狀態：「做完」只能在完成時出現，不要拿閒聊句充數
5. 多角色時，遮住名字也要看得出誰在說：語氣、句長、用詞要有差異

## 通過條件
遮住名字抽 5 句，使用者能猜出至少 4 句是誰說的；否則回頭改人設的「說話風格」欄。

## 輸出檔：`app/public/characters/<id>/dialogue.json`
agent 寫完對白庫後，同時輸出這份 JSON（沒有這個檔，頁面就不顯示氣泡）：
```json
{ "working": ["…"], "done": ["…"], "stuck": ["…"], "idle": ["…"], "click": ["…"], "greet": ["…"] }
```
頁面行為：剛打開出現 `greet`；狀態變 working 說 `working`；沒事時每 16–24 秒有 70% 機率說一句 `idle`；點角色說 `click`。`done`、`stuck` 預留給之後的狀態（目前頁面尚未觸發）。
